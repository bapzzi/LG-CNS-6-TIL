4일 내내 새 마법이 나온 게 아니다. **순수 JS로 손수 하던 일이 하나씩 React 쪽으로 넘어갔고**, 마지막 날 그 조각들이 앱 한 벌로 조립됐다.

## 1. 문자열 조립이 컴포넌트가 됐다 — 6일차

6일차는 오전과 오후가 **같은 일을 두 번** 한 날이다. 오전엔 순수 JS로 카드 목록을 만들고, 오후엔 React로 같은 것을 다시 만들었다.

```js
// 오전 — 순수 JS
container.innerHTML = items.map(renderCard).join("");
```
```jsx
// 오후 — React
{books.map((book) => <Book bookName={book.bookName} />)}
```

- 배열을 `.map()`으로 도는 방법은 **그대로**다. 바뀐 건 결과물 — 문자열이 아니라 컴포넌트.
- 그래서 잡일 두 개가 사라졌다. `.join("")`(이어붙이기)과 `innerHTML`(화면에 꽂기). React가 배열 속 엘리먼트를 알아서 순서대로 그리기 때문이다.
- 부품에 값을 넣는 통로가 **props**다. 부모가 지은 이름으로 보내고, 자식은 읽기만 한다.

여기서 만든 화면은 전부 "한 번 그리고 끝"이었다. 값이 바뀌어도 화면이 안 따라온다 — 그게 다음 날의 주제가 된다.

## 2. 값이 화면을 끌고 간다 — 7일차

7일차의 핵심 실험은 **일부러 실패하는 코드**였다. 입장/퇴장 버튼으로 인원수를 세는데, 일반 변수로 만들면 콘솔 숫자만 올라가고 화면은 0에 멈춘다.

- 이유: 컴포넌트는 함수고, 화면의 `{cnt}`는 함수가 실행되던 순간의 값이다. React는 일반 변수를 **감시하지 않아서** 바뀐 걸 모르고, 모르니 다시 그릴 이유도 없다.
- 해법이 `useState`. 돌려주는 두 번째 것(`setCnt`)이 값을 바꾸면서 **React에 신고**까지 한다. 신고를 받아야 컴포넌트 함수가 다시 돌고 화면이 새 값으로 그려진다.
- `setCnt`는 대입이 아니라 **예약**이다. 다음 줄에서 읽으면 옛 값이다 — 새 값은 다음 실행에서 생긴다.
- 렌더가 끝난 뒤 할 일(데이터 요청·로그)은 `useEffect`에 두고, 두 번째 인자(의존성 배열)로 **몇 번 돌지**를 정한다. `[]`면 처음 한 번 — 배열을 빼먹으면 요청→상태 변경→재렌더→또 요청의 무한 반복이 된다.

데이터가 오는 길도 이날 깔렸다: `.env`(주소를 코드 밖으로) → `axios.create`(기본 주소를 박은 도구 하나를 앱 전체가 공유) → `json-server`(db.json 한 장을 서버처럼). **db.json 최상위 키가 그대로 URL 경로가 된다**는 것까지.

## 3. 입력을 쥐고, 화면 사이를 잇는다 — 8일차

8일차는 로그인 기능 한 벌을 처음부터 끝까지 만들었다. 조각 다섯 개가 순서대로 나왔다.

| 단계 | 장치 | 요점 |
|:----:|------|------|
| 입력받기 | `value` + `onChange` | 입력칸의 값을 state가 쥔다(**controlled component**). 화면과 코드가 어긋날 수 없다 |
| 물어보기 | axios 쿼리 조회 | 맞는 사용자인지는 서버만 안다 |
| 갈라지기 | 응답 판정 | **조회 성공(200) ≠ 대상 존재** — 판정은 `data.length`로 |
| 화면 옮기기 | react-router-dom | 페이지를 새로 받는 게 아니라 **컴포넌트를 교체**한다(SPA) |
| 화면 고르기 | `{flag ? A : B}` | 로그인 여부 같은 값 하나로 화면을 가른다 |

- 화면 사이에 값을 실어 보내는 길이 네 갈래(state·쿼리스트링·경로 변수·localStorage)인데, 기준은 두 가지다 — **주소창에 보여도 되는가, 주소를 복사해 줬을 때 따라가야 하는가.**
- `&&` 조건부 렌더링에는 함정이 하나 있다. `0`만 글자로 그려진다 — 개수를 조건으로 쓸 땐 `length > 0`으로.

## 4. 조각 전부를 한 앱으로 — 9일차

마지막 날은 새 개념이 아니라 **조립**이었다. 미니 블로그 MVP — 글 목록/글 보기/댓글 보기/글 작성/댓글 작성.

- 기능 목록이 그대로 화면과 API 표가 됐다. **기능 → 데이터 → 화면** 순서.
- 입력칸이 늘어난 회원가입 폼에서 useState를 칸마다 쪼개지 않고 **객체 하나 + 공용 핸들러**(`[name]: value`)로 묶었다. 고칠 곳의 개수 자체를 줄여 실수를 줄이는 방식.
- 댓글을 달면 목록 전체를 다시 받아올지, 새 댓글 한 건만 state에 붙일지 — 정답이 아니라 **트레이드오프**다. 혼자 보는 화면이면 추가로 충분하고, 여럿이 쓰는 화면이면 재조회가 맞다.
- 실습 방식도 이날 바뀌었다. 코드를 따라 치는 게 아니라 **AI에게 시키는 실습** — 내 몫은 기능 정의·URL 설계·요구사항이었고, 검수 기준이 되어 준 것이 앞서 손으로 잡아둔 그 표들이었다.

- `class` → `className` **손버릇** — 개념은 알아도 붙여넣기 순간마다 재발(3회째)
- 라우트 파라미터 문법 — `read/:id`의 `:`는 경로 조각 첫 글자일 때만 파라미터라는 것
